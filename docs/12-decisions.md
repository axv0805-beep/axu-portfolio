## ADR-001 · 视觉基线

**背景**：用户要求「简约大气、类似 Claude 的风格」；作品是绝对主角，界面不能抢戏。

**决策**：
- 取 Claude 的**气质**而非**外观**：暖白纸面、衬线标题、陶土色点缀、细线分隔、大量留白。
- 不复制 Anthropic/Claude 的商标、Logo、插画、专有字体；不使用其品牌色值。
- 建立自有 token（04）与唯一签名「册页线」；所有页面只能使用 token 中的颜色与字号。

**后果**：
- 视觉一致性强，新页面只需组合既有 token。
- 陶土色 `#C05B3C` 对纸色对比 3.9:1，**不能**用于正文小字；正文链接用 `--accent-ink #9C4527`（5.7:1）。
- 换主题时只改 `:root`，不动组件。

**放弃**：深色科技风（与「纸」冲突）、大图渐变风（抢作品）、纯黑白（缺少温度）。

## ADR-002 · Next.js 全栈单体

**背景**：前台展示 + 后台 CRUD + 上传；单管理员；希望一条命令部署。

**决策**：
- Next.js 15 App Router 同时承载前台、后台、API。
- 不拆前后端仓库；不做独立 BFF。
- 部署为单容器 + 单进程。

**后果**：
- 一套类型、一套校验、一套部署，迭代快。
- 前台与后台共享组件库，但后台路由单独 code split，避免把编辑器打进首屏。
- 若未来拆服务，`src/lib/` 已是天然边界；API 契约（08）可直接复用。

**放弃**：Vite SPA + Express（两套构建、两套鉴权）；Astro（后台交互仍需 SPA）。

## ADR-003 · SQLite + Prisma

**背景**：单管理员、作品量级预计 < 1000、部署环境是一台小服务器；需要易备份。

**决策**：
- SQLite（WAL 模式）+ Prisma 6。
- 连接初始化执行 `journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`。
- 迁移文件入库，启动时 `prisma migrate deploy`。

**后果**：
- 备份 = 复制一个文件（配合 `.backup` 保证一致性）。
- 单写者：并发写会排队；单管理员场景可接受。
- 切 PostgreSQL 时：改 `provider`、`DATABASE_URL`、重建迁移；JSON 字段在 PG 用 `jsonb`，查询代码基本不变。

**放弃**：PostgreSQL（运维成本）；JSON 文件存储（并发/查询/迁移都弱）。

## ADR-004 · Block JSON

**背景**：作品正文需要图文混排、视频、提示词等结构化内容；后台要可视化编辑；前台要统一排版。

**决策**：
- `Work.content` 存 `Block[]`（JSON），每个块有 `id`、`type`、`version` 与类型字段。
- 块类型 10 种：paragraph / heading / image / gallery / video / audio / quote / prompt / link / divider；另加未知类型占位分支，渲染器共 11 个分支。
- 用 Zod 做运行时校验；未知类型降级为占位，不整页报错。
- 渲染由 `BlockRenderer` 的 `type → component` 映射完成，不使用 `dangerouslySetInnerHTML`。

**后果**：
- 排版由设计系统控制，作者不会把页面弄乱。
- 新增块类型 = 加一个 schema 分支 + 一个编辑器表单 + 一个展示组件；旧数据不受影响。
- 全文检索弱（JSON 内文本）；首版不需要，P1 可加 FTS5 或生成 `searchText` 列。

**放弃**：富文本 HTML（样式失控、XSS 面大）；Markdown 全文（无法表达图集/视频/提示词卡片）。

## ADR-005 · 读写分离的请求路径

**背景**：RSC 直接查库最简；但写操作需要统一鉴权、校验、错误码、缓存失效。

**决策**：
- 读：Server Component 直接调用 `src/lib/db` 查询（不经 HTTP）。
- 写：客户端组件 `fetch('/api/admin/**')`；Route Handler 内完成 Origin → 会话 → Zod → Prisma → revalidate。
- 不使用 Server Actions 作为主路径（避免与 REST 契约两套错误模型）。

**后果**：
- 前台无额外网络跳转；后台错误结构统一，表单可映射字段。
- 所有写入口集中，便于审计与限流。
- 需要手动维护 `revalidatePath` 清单（09 §3.3）；漏掉会看到旧页面。

**放弃**：全 Server Actions（渐进增强好，但契约分散）；GraphQL（过重）。

## ADR-006 · 本地存储 + 适配器

**背景**：首版单机部署，不希望强制对象存储；但未来可能上 S3/CDN。

**决策**：
- 文件写 `data/uploads/YYYY/MM/{uuid}.webp`；DB 存相对 key。
- `src/lib/storage.ts` 暴露 `put/get/delete/publicUrl`；首版本地实现。
- 通过 `/uploads/[...path]` 受控读取，不直接把上传目录暴露为静态目录。

**后果**：
- 零外部依赖即可运行；备份需同时备份 DB 与 uploads。
- 容器必须挂卷，否则重建丢文件（部署文档已强调）。
- 换 S3 时改一个实现文件 + 环境变量；URL 生成逻辑集中。

**放弃**：直接写 `public/uploads`（构建产物与运行时数据混在一起，Docker 下易丢）；强制 S3（提高首次部署门槛）。

## ADR-007 · 单管理员会话

**背景**：个人站点，只有站主需要登录；不需要注册、角色、找回密码邮件。

**决策**：
- `User` 表 P0 仅一条 `admin` 记录；`role` 预留 `editor`，本期不开放；bcrypt cost 12。
- iron-session 加密 Cookie；7 天；httpOnly、sameSite=lax、生产 secure。
- 登录限流 5 次/15 分钟（内存）。
- 改密后 `sessionEpoch + 1`，旧 Cookie 的 `epoch` 不匹配，全部失效。

**后果**：
- 无会话表、无 Redis；重启不掉登录（Cookie 自包含）。
- 多实例部署时限流不共享（首版单实例，可接受）。
- 忘记密码需 CLI 重置（文档提供命令）。

**放弃**：NextAuth（provider 体系过重）；数据库会话（多一张表、多一次查询）。

## ADR-008 · 简体中文、PC 优先

**背景**：需求明确「PC 网页端」；内容与文案均为中文。

**决策**：
- 界面语言简体中文；`<html lang="zh-CN">`。
- 以 1280–1600 为主设计宽度；≥ 1600 容器 1280；< 1024 仅保证可用（不横向滚动、可读、可点）。
- 字号、行高按中文排版设定（正文 1.7–1.8，中英文间加空格）。
- 不引入 i18n 框架；文案集中为常量，便于未来抽取。

**后果**：
- 移动端不是重点，但不会坏；后续要做移动优先需重排首页 Hero 与后台表格。
- 未来多语言：文案抽到 `messages/zh-CN.ts`，路由加 `[locale]`；内容层另加 `locale` 列/翻译表（`siteNameEn` 只是英文展示名，不是 i18n 方案）。

## ADR-009 · RSC 优先、最小水合

**背景**：展示型站点，交互少；首屏 JS 越小越好。

**决策**：
- 页面、卡片、正文渲染默认 Server Component。
- 只有筛选下拉、复制、加载更多、Toast、后台表单是 Client Component。
- 不引入全局状态库；局部 `useState` 足够。
- 第三方脚本为零（无统计、无客服）。

**后果**：
- 前台首屏 JS 可压到 120 KB 以内。
- 交互需要接受「整页/局部 RSC 刷新」；后台保存后用 `router.refresh()`。
- 动画只能用 CSS；复杂手势需引入库时单独评估。

---

## ADR-010 · Radix 无头原语

**背景**：弹窗、下拉、开关、Toast 的可访问性与焦点管理自研成本高。

**决策**：
- 使用 Radix Primitives（Dialog、DropdownMenu、Switch、Toast、Tabs、Tooltip、Select）。
- 样式全部用 Tailwind + token 覆盖；不引入任何预置主题。
- 只在后台与前台筛选处打包；展示页不加载。

**后果**：
- 键盘与读屏行为开箱可用。
- 需要自己写视觉层，组件数量受控（约 12 个）。
- 版本升级注意 peer 依赖；锁定 minor。

**放弃**：shadcn 整包（带入默认审美与多余组件）；Headless UI（Vue 倾向、组件少）。

---

## ADR-011 · 视频外链优先

**背景**：AIGC 视频文件大；本地磁盘与带宽有限；B 站/YouTube 已有播放体验。

**决策**：
- 视频块首选外链（B 站 iframe、YouTube iframe）；域名白名单。
- 本地上传仅 ≤ 100 MB，作为短片兜底。
- 外链播放器使用 `iframe` + `loading="lazy"`；不自动播放。

**后果**：
- 节省磁盘与带宽；播放体验依赖第三方。
- 需要处理第三方 Cookie/地区限制；提供「在新窗口打开」降级。
- 若未来要自托管大视频，需接对象存储 + 转码（P2）。

## ADR-012 · 浅色单主题

**背景**：纸面视觉本身依赖暖白；深色模式会破坏「纸」的隐喻，且增加维护面。

**决策**：
- 首版只做浅色；`prefers-color-scheme: dark` 不做自动切换。
- `:root` 中预留 `[data-theme="dark"]` 的映射位（注释形式），不实现。
- 深色只用于页脚与「深色区块」局部，不构成主题。

**后果**：
- 减少一半视觉验收工作。
- 用户夜间访问偏亮；若后续要做，需重新定义纸/墨在深色下的对应关系，而非简单反色。

## 变更流程

1. 新决策先在本文件追加 ADR（编号递增），写清背景、选项、后果。
2. 影响需求的，同步改 `02-requirements.md` 并在 ADR 中注明。
3. 影响数据结构的，先改 `07-data-model.md` 与迁移，再改代码。
4. 被取代的 ADR 标「已废弃（被 ADR-XXX 取代）」，不删除。
